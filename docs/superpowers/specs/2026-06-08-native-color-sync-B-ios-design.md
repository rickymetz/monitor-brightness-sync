## 2. `ColorSyncCore` extraction

Create a platform-agnostic SwiftPM package `ColorSyncCore/` (own `Package.swift`, library product `ColorSyncCore`) consumed by both apps.

**Files that move into `ColorSyncCore/Sources/ColorSyncCore/`:**
- `ColorCorrection.swift` (`ColorCorrection`, `RGB`, `PatchSamples`)
- `ColorMatcher.swift` (`ColorMatcher`, `DisplayMeasurement`)
- `PatchCardLayout.swift`
- `PatchCardAnalyzer.swift`
- `ColorSyncMessages.swift` (`DisplayRef`, `MacToPhone`, `PhoneToMac`, `ColorSyncPeer`)
- `ColorSyncAdjust.swift`
- **New** `TransferFormula.swift`: the pure `Channel` struct + `transferFormula(dim:correction:) -> (red:Channel, green:Channel, blue:Channel)` extracted out of `DisplayColorState`.
- **New** `PairingPayload.swift`: pure parser/builder for the `mbsync://pair?h&p&k` QR URL.
- **New** `FrameCodec.swift`: pure length-prefixed framing helpers (encode a body to a UInt32-BE-prefixed `Data`; a streaming decoder that yields complete bodies). Shared by both transports.

**Stays app-side (macOS), gains `import ColorSyncCore`:**
- `DisplayColorState.swift` — the stateful gamma-writing class; now calls `transferFormula(...)` from core.
- `SyncController.swift`, `AppDelegate.swift`, `ColorSyncWindowController.swift`, `ColorSyncTransport.swift`, `ColorSyncQR.swift`, `PatchCardWindow.swift`.

**macOS `Package.swift`:** add `.package(path: "ColorSyncCore")` and make the `SyncBrightness` target depend on the `ColorSyncCore` product.

**Test harness:** the framework-free `color-checks` driver compiles only the **core** source files (now under `ColorSyncCore/Sources/ColorSyncCore/`) + `Tests/ColorChecks/main.swift` — all pure, no app files, so the loose-`swiftc` approach has no module-import conflict. Update the paths in `run-tests.sh`. The stateful `DisplayColorState` is covered by `swift build`. The Task-2 `transferFormula` tests move to target the core function.

**Rationale:** this is the friction flagged in Plan A. Extracting the pure `transferFormula` (the only tested part of `DisplayColorState`) into core lets the loose test driver avoid compiling any `import ColorSyncCore` app file.

## 3. iOS app architecture (SwiftUI + AVFoundation, min iOS 16)

A thin app; logic lives in `ColorSyncCore`.

### Components
- **`MBSyncApp`** (`@main` SwiftUI App) — root navigation: Pairing → Capture → Done.
- **`PairingView` + `QRScannerView`** — `AVCaptureMetadataOutput` reads a QR; `PairingPayload.parse(url:)` (core) yields `{host, port, psk}`; hands off to the client.
- **`ColorSyncClient`** — `NWConnection` TLS-PSK client. Identity `"colorsync"`; PSK = `Data(pskString.utf8)` (the percent-decoded base64 *text* bytes, matching the Mac). Uses `FrameCodec` (core) for length-prefixed UInt32-BE JSON frames. Decodes `MacToPhone`, encodes `PhoneToMac` (the same core Codable types). Publishes received messages on the main actor; exposes `send(_:)`.
- **`CameraController`** — wraps `AVCaptureSession`:
  - Live preview via `AVCaptureVideoPreviewLayer` (in a `UIViewRepresentable`).
  - `lock()`: set `whiteBalanceMode = .locked` and `exposureMode = .locked` (fall back to `.custom` with fixed ISO/duration if `.locked` unsupported) on the active `AVCaptureDevice`, after the Mac shows mid-gray on the reference so exposure settles sensibly. Settings are then frozen for the session.
  - `AVCaptureVideoDataOutput` delivers frames → CGImage. A frame is offered to `ColorSyncCore.PatchCardAnalyzer`.
  - **Auto-capture:** when the analyzer returns non-nil `PatchSamples` for N consecutive steady frames (a pure `CaptureGate` helper decides "stable"), capture that frame's samples. A manual shutter button is shown as fallback and after a timeout.
- **`SessionCoordinator`** (`@MainActor` view model) — maps incoming `MacToPhone` to UI state + camera actions and emits `PhoneToMac`:
  - `prepareLock(referenceLabel)` → prompt "Aim at <ref>, hold steady"; on stable/explicit lock → `CameraController.lock()` → send `.locked`.
  - `capture(displayID,label)` → prompt "Aim at <label>"; auto-capture → `.samples(displayID, samples)`; analyzer failure/timeout path → `.error(reason)`.
  - `retake(displayID,hint)` → show hint, continue capturing the same display.
  - `done` → Done screen.

### Pure helpers (unit-tested in core)
- `PairingPayload.parse(url:)` / `.build(...)` — round-trip + percent-decode of `k`.
- `FrameCodec` — encode/decode round-trip, split-buffer reassembly, oversize rejection.
- `CaptureGate` — given a sequence of analyzer outcomes (hit/miss), decides when "stable enough" to auto-capture (N consecutive hits). Pure, testable without a camera.

## 4. Wire contracts (must match Plan A exactly)

Reusing core's `ColorSyncMessages`, `PatchCardAnalyzer`, `PatchCardLayout` makes most contracts hold by construction. Explicitly:
- **QR:** `mbsync://pair?h=<host>&p=<port>&k=<psk>`; `k` percent-decoded (Mac encodes with `.alphanumerics` allowed, so base64 `+`/`/`/`=` are escaped).
- **TLS-PSK:** ciphersuite `TLS_PSK_WITH_AES_128_GCM_SHA256`; identity literal `"colorsync"`; key = UTF-8 bytes of the decoded base64 **string** (not the 16 decoded bytes) — matches the Mac's `Data(psk.utf8)`.
- **Framing:** 4-byte big-endian UInt32 body length, then JSON body; max 4 MB.
- **JSON:** Swift default `Codable` enum representation (single-key object per case), from the shared types. `PatchSamples` = `{white,gray50,gray25,red,green,blue}`, each `{r,g,b}` in 0…1.
- **Geometry:** `PatchCardLayout` (3×2, inset 0.12, bottom-left origin; row 1 white/gray50/gray25, row 0 red/green/blue; fiducials TL=cyan, TR=magenta, BL=yellow, BR=white). Analyzer assumes a roughly axis-aligned shot (no perspective rectification) — fine for the locked, framed capture.

## 5. Xcode project & repo layout

- New top-level `ios/` directory: `project.yml` (xcodegen), `Sources/` (the SwiftUI/AVFoundation code), `Info.plist` bits (camera usage description `NSCameraUsageDescription`, local-network usage `NSLocalNetworkUsageDescription` + a Bonjour/`NSBonjourServices` entry is not needed since we use a direct IP, but `NSLocalNetworkUsageDescription` IS required for `NWConnection` on the LAN).
- `project.yml` references the local `ColorSyncCore` package (`packages: ColorSyncCore: { path: ../ColorSyncCore }`) and links it to the app target; deployment target iOS 16; bundle id placeholder `com.rick.mbsync` (owner repoints to their team).
- `xcodegen generate` (run from `ios/`) produces `ios/MBSync.xcodeproj` (the generated `.xcodeproj` may be git-ignored or committed — default: commit `project.yml`, git-ignore the generated `.xcodeproj`).
- Build-verify: `xcodebuild -project ios/MBSync.xcodeproj -scheme MBSync -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build`.

## 8. Risks / notes

- **Cannot runtime-test the camera/lock/network here** — these are compile-verified only; the owner validates on device. Code is kept thin and the testable logic is pulled into pure core helpers to maximize what *is* verified.
- **`whiteBalanceMode = .locked` support** varies by device; the lock path falls back to `.custom` with fixed gains/ISO/duration. Validate on the target iPhone.
- **NWConnection TLS-PSK on iOS** must mirror the macOS PSK byte derivation precisely; `FrameCodec` + shared message types reduce drift, but the PSK-bytes detail (UTF-8 of the base64 text) is the easiest thing to get subtly wrong — called out and worth an explicit check during device bring-up.
